# k-proj-cooperacao-agentes
versao: C.A.O.S v1.1

## OBJETIVO

Definir como:
- usuário
- agente_orquestrador
- agente_executor
- RAG
- skills

cooperam operacionalmente.

---

# PRINCÍPIO CENTRAL

Nenhum agente:
opera sozinho.

O sistema:
funciona por cooperação coordenada.

---

# PAPÉIS

---

## USUÁRIO

Responsabilidade:
- definir objetivos
- validar decisões
- aprovar mudanças críticas
- orientar visão do produto

Função:
direção estratégica humana.

---

## agente_orquestrador

Responsabilidade:
- arquitetura
- modelagem
- raciocínio
- decisões estruturais
- orquestração

Função:
orquestrador cognitivo.

---

## agente_executor

Responsabilidade:
- executar alterações
- criar arquivos
- atualizar módulos RAG
- aplicar patches
- manter taxonomia

Função:
executor operacional.

---

## RAG

Responsabilidade:
- preservar memória operacional
- fornecer contexto mínimo
- manter coerência histórica

Função:
memória viva do sistema.

---

## SKILLS

Responsabilidade:
padronizar operações recorrentes.

Função:
especialização operacional.

---

# FLUXO OPERACIONAL

1. usuário define objetivo
2. agente_orquestrador classifica tarefa
3. index.md seleciona módulos
4. RAG fornece contexto mínimo
5. skill especializada é ativada
6. agente_executor executa alterações
7. usuário valida resultado
8. RAG é atualizado
9. sistema preserva memória

---

# PRINCÍPIO DE CONTEXTO

agente_orquestrador:
deve pensar.

agente_executor:
deve executar.

RAG:
deve lembrar.

Usuário:
deve validar.

---

# PRINCÍPIO DE MEMÓRIA

Toda evolução importante:
deve ser refletida no RAG.

Objetivo:
preservar continuidade entre sessões.

---

# PRINCÍPIO DE MODULARIDADE

Cada agente:
deve atuar:
em sua especialidade.

Evitar:
sobreposição desnecessária.

---

# PRINCÍPIO DE SEGURANÇA

Mudanças críticas:
devem ser aprovadas pelo usuário.

Exemplos:
- migrations destrutivas
- alterações RLS
- mudanças arquiteturais
- exclusões
- automações sensíveis

---

# PRINCÍPIO DE ESCALABILIDADE

O modelo:
deve funcionar:
- em múltiplos projetos
- em múltiplos repositórios
- em múltiplos agentes
- em equipes humanas

---

# PRINCÍPIO DE ECONOMIA COGNITIVA

Objetivo:
mínimo contexto
máxima precisão.

Evitar:
- repetição
- contexto excessivo
- documentação gigante
- regeneração completa

---

# PRINCÍPIO DE EVOLUÇÃO

O sistema:
deve melhorar continuamente:

- taxonomia
- skills
- regras
- automação
- modularidade

Sem:
perder coerência operacional.

---

# RESULTADO ESPERADO

O C.A.O.S deve permitir:

- desenvolvimento assistido por IA
- memória persistente
- continuidade operacional
- múltiplos agentes cooperando
- redução de custo cognitivo
- preservação arquitetural
- escalabilidade de engenharia
